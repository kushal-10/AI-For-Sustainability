# AI-For-Sustainability
End-to-end LLM pipeline to quantify the impact of AI towards SDGs in German Firms.


## Setup

Clone this repo and install requirements 

```python
git clone https://github.com/kushal-10/AI-For-Sustainability.git
cd AI-For-Sustainability
```
```python
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

The data - PDF files for the annual reports should be stored in `data/reports/FIRM/YEAR.pdf`

## Pre-Processing

1. Convert files from `.pdf` to `.txt` using a base PyMuPDF package. This will create the text files under `data/texts/FIRM/YEAR/results.txt`

```python
python3 src/preprocessing/pdf2text.py
```

2. Check if any files got corrupted/Contains text in other languages. If, so use `tesseract` OCR to extract text. [`corrupted_files.py` and `check_non_ascii.py`]

Have these reports saved under `data/reports_corrupted` then run:
```python
python3 src/preprocessing/tesseract.py
```

3. Use a semantic chunker to split the text files into chunks based on the similarities between sentences - [langchain text-splitters](https://reference.langchain.com/python/langchain_text_splitters/).
```python
python3 src/preprocessing/splitter.py
```
This will create a `*/splits_semantic.json` for each `*/results.txt` under `data/jsons`.

## Filtering the passages

There are certain reports only available in `German`, so we collect a list of tech and sdg keywords first in `English` and then translate them. A list of collected keywords and their translations is available under `kw_data`

Run the following to filter the passages and create a DuckDB for each set of hits in tech and SDG:

```python
python3 src/filtering/tech_filter.py \
  --root data/jsons \
  --kw_en kw_data/keywords_tech.json \
  --kw_de kw_data/keywords_tech_de.json \
  --out_db data/dbs/tech_hits.duckdb \
  --table tech_hits

python3 src/filtering/sdg_filter.py \
  --root data/jsons \
  --kw_en kw_data/keywords_sdg.json \
  --kw_de kw_data/keywords_sdg_de.json \
  --out_db data/dbs/sdg_hits.duckdb \
  --table sdg_hits
```

## Classification into Symbolic/Substantive

1. For each filtered passage, we then use `gpt-4.1-mini` to classify each mention of the Tech/SDG into a Symbolic or a Substantive mention. The exacts prompts used can be found in `src/gpt_classifier/objects.py`. 
The following creates jsonl batch objects and submits them over a 24h completion window

```python
export OPENAI_API_KEY=your_key
python3 src/gpt_classifier/batches.py -- build
python3 src/gpt_classifier/batches.py -- submit
```

The status of batches can be checked by:

```python
python3 src/gpt_classifier/poll_batches.py
```

2. After all the batches have a `completed` status, the results can be collected by running:

```python
python3 src/batching/collect_results.py
```

## Post-Processing

1. The classifications can be verified by running

```python
python3 src/postprocessing/check_classifications.py
```

This verifies that all filtered keywords were classified into one of `Substantive/Symbolic`. If, not those passages are sent to the openai client again for classification. This can be done by running
```python
python3 src/postprocessing/fix_err_classifications.py
```

2. After this the next step is to create a DuckDB that contains all metadata for a given passage including the classifications. This can be done by running
```python
python3 src/postprocessing/apply_classifications.py
python3 src/postprocessing/apply_fixed_classifications.py # Run only if `unclassified` string found in openai client responses, and were submitted again by running fix_err_classifications.py
```

This creates two new DuckDBs `{sdg/tech}_hits_classified.duckdb`.

3. A final result csv that contains the raw frequencies of the classifications and filter can be generated by running
```python
python3 src/postprocessing/build_company_year_summary.py
python3 src/postprocessing/merge_kw_filter.py
```
4. More metadata like token counts, language of report etc. is added to the company year summary by running 

```python
python3 src/postprocessing/add_lang.py
python3 src/postprocessing/add_token.py
```
This also includes empty entries for firm-year that got entirely filtered out in the first pass, resulting in all null values.
